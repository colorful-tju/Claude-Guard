# Claude Guard · Claude 安全启动器

**先验证网络防护，再启动 Claude。**

面向 macOS 的小型桌面工具，为通过 HTTP 代理使用 Claude Desktop 与本机 Claude Code 的用户提供临时出口限制、启动前验收与运行中监控。使用结束后，按顺序退出受保护进程并恢复本工具修改的网络状态。

> **0.5.3 测试版 · macOS 14+ · 源码可见 / 非商业 / 禁止二次开发**
> 个人测试版安装修复，尚未完成 Apple 公证，不是 Anthropic 官方软件。作者：[colorful / @colorful-tju](https://github.com/colorful-tju)。许可见 [LICENSE](LICENSE)。

## 为什么需要它

系统代理设置并不覆盖所有程序；TUN 接管也不能单凭“浏览器显示代理 IP”证明不存在旁路。某些主动绑定物理接口的 UDP、DNS 或 STUN 请求，可能暴露物理网络的公网出口。

Claude Guard 面向这样的使用场景：你已经准备好一个 **数字 IPv4 的 HTTP/TCP 代理节点**，希望使用 Claude 时，仅保留经过验证的代理网络路径，并在无法继续验证时停止受保护的应用。

它不是代理客户端，不提供节点，不切换订阅，也不靠修改浏览器 DNS 来制造安全状态。它会临时限制**整台 Mac 的新出站流量**，因此同一期间其他应用也可能受到影响。

## 主要功能

| 功能 | 实际行为 |
|---|---|
| 安全启动 Claude | 检查配置、核心身份、真实网关连接和 TUN；加载 PF 限制；完成出口与负向探针后启动 |
| 仅验证防护 | 完成同一套防护验收，进入 ARMED，但不启动 Claude |
| 临时出口限制 | 放行回环、已验证 TUN、指定物理接口到代理网关的 TCP；默认阻断其他新出站 IP 路径 |
| 两个 HTTPS 出口检测 | 展示 ipify 与 Webshare 返回的 IPv4，并与用户配置比较；不推断网关或国家 |
| 临时 IPv6 管理 | 在 OFF 且 Claude/Code 已退出时关闭或启用 Automatic，保存并恢复原设置 |
| 持续监控 | 检查 PF、核心/TUN、路由与进程前提，周期复核出口；异常时显示中文提示及停止原因 |
| 菜单栏 | 查看状态、打开窗口、关闭防护；关闭窗口不结束防护 |
| 诊断和独立恢复 | 导出反馈；提供不依赖 UI 的离线恢复工具 |

顶部绿色表示**当前 ARMED 且防护已验证**；黄色表示尚未启用或正在处理；红色表示检测异常、条件不满足或自动停止。出口 IP 匹配本身不会将状态变绿。

## 兼容范围

本版取消了对代理 GUI 品牌和节点名称的固定要求，但仍需安装时登记**实际持有 TUN 与网关 TCP socket 的核心可执行文件**及其配置路径。

目前配置读取器支持：

- 单节点的 Mihomo / Clash YAML，节点类型 `http`；节点名任意但不得为空。
- 服务商明确支持的数字公网 IPv4 endpoint 与端口。
- 不启用 TLS-to-proxy、UDP、dialer-proxy 或额外传输；HTTPS 网站通过 HTTP CONNECT 访问。
- 核心可通过 macOS 原生 socket 信息证明其持有唯一 TUN，并有到指定网关的已建立 TCP 连接。

域名 endpoint、多节点/外部 provider、SOCKS5、UDP 隧道、任意 VPN 或无法证明核心归属的实现均不属于本版支持范围。更换核心版本后需重新登记签名。**未对其他客户端完成实机兼容性认证**，不能把同样的出口 IP 当成兼容证明。FLClash 的既有路径可作为安装快捷方式保留，但运行时不要求其 GUI 存在。

## 首次使用

### 1. 打开 DMG

从 [Releases](https://github.com/colorful-tju/Claude-Guard/releases/tag/v0.5.3) 获取对应架构的 DMG：`Claude-Guard-0.5.3-macOS-AppleSilicon-arm64.dmg` 或 `Claude-Guard-0.5.3-macOS-Intel-x86_64.dmg`。分别提供 Apple Silicon 与 Intel 测试包，适用于 Mac、macOS 14 或以上；不需要 Xcode、源码或终端构建命令。macOS 26 使用系统 Liquid Glass，旧系统使用材质回退。

打开映像，双击唯一的「双击安装 Claude Guard.app」，**无需拖入应用程序文件夹**。根据图形提示完成管理员授权，成功后选择打开 App。更新前请先在旧版菜单栏选择「恢复并退出」。不要直接删除旧助手或恢复记录。

### 2. 完成首次准备

图形程序会放置 App、登记并启动空闲助手，不开启防护、不切换网络。默认可选择标准位置的 FLClash；其他兼容核心通过文件选择框选定实际核心可执行文件及运行配置。配置文件须由当前用户拥有，核心签名须有效；不能把 GUI App 目录当成核心文件。

管理员授权是 PF、进程控制和恢复所需的系统权限，不能由 DMG 免除。日常使用不重复请求这项授权；更新、移除或重新登记仍需授权。

本测试 DMG 使用本地 ad-hoc 签名，尚未完成 Developer ID 签名及 Apple 公证。Intel 包仅完成交叉编译与静态检查，尚未进行 Intel 真机验收。它不是已经可无提示公开分发的正式版。若下载后被系统拦截，先核对来源与系统安全提示，不要关闭 Gatekeeper 或 SIP。正式 Release 的签名、公证将在发布前处理。

### 3. 手动准备代理

退出 Claude Desktop、Claude Code 及其会话。手动准备兼容代理的 HTTP 节点与 TUN；先确认普通网页能访问。启动器不会替你开关代理、DNS、订阅或节点。

### 4. 填写网络设置

首次使用不提供任何私人地址，也不导入开发版保存的偏好。后续会记住你自己的设置，但不会记住“已确认”授权或自动开启防护。

| 字段 | 从哪里取得 |
|---|---|
| Gateway IPv4 | 服务商提供并明确支持的数字代理服务器地址，或已核对的代理软件节点配置 |
| 端口 | 服务商或当前节点详情；公网 IP 网站无法测出代理端口，0 表示未填写 |
| 物理接口 | 实际连接网络的接口，例如 Wi-Fi 通常为 en0；需按本机情况核对 |
| 预期出口 IPv4 | 准备代理后运行内置检测，点击“检测并填入出口 IP”，两个服务一致且结果新鲜时自动填写，再核对服务商预期 |

**网关 ≠ 出口。** IP 检测只用于预期出口，绝不自动推断网关或端口。即使两者恰好相同，也要分别核对。问号按钮提供同样的填写说明。

点击“重新检测配置”，核对候选网关和指纹，点击「确认代理端点」。若提示 IPv6 默认路由存在，在 OFF 且 Claude/Code 退出后点击临时 IPv6“关闭”。本版不会把 `ipv6: false` 当作系统 IPv6 已关闭的证明。

### 5. 先验收，再日常使用

先点击“仅验证防护”，等待明确的 **ARMED / 绿色**。期间不要更换节点或网络。按 [公开版验证手册](docs/完整验证手册.md) 检查出口、正常网页和 OFF 恢复。验证成功后，再使用“安全启动 Claude”。

## 各功能与安全机制

### 防护是如何生效的

SwiftUI 是控制界面；root GuardDaemon 持有安全事务；独立 Probe 执行检测。安装时登记 UI 和核心的签名身份，IPC 同时检查 UID、audit token 和构建身份。无需关闭 SIP，不依赖 Network Extension entitlement。

PF 规则使用独立子 anchor，保留 Apple 主规则，通过自身 enable token 管理引用。默认出站拒绝不限定当前接口列表：新接口不会在监控响应前自动获得放行。只允许精确验证的 TUN，不按 `utun*` 统放。

启动前必须看到核心的真实 TCP 网关连接与 TUN 归属；随后要求两个 HTTPS 回显符合预期，以及绑定物理接口的 TCP、UDP/STUN 探针失败并使对应 block 计数增加。最终再核对本地前提快照，防止用过期验证结果启动。

### 运行中的处理

本地前提约每秒检查，出口约每 15 秒复核。进程有 UDP socket 不直接等同于泄漏；PF 承担先行阻断，进程观测只提供有限诊断。无法维持关键前提时，请求结束受保护的 Claude/Code，并解释原因。未知来源的 PF 阻断不会伪称来自 Claude。

Claude Code 的已识别子进程纳入生命周期管理，但不承诺覆盖远程执行器、虚拟机或绕过系统保护的特权进程。

### 关闭和恢复

点击“关闭防护”时无需先退出 Claude，工具自动执行：

1. 保持 PF，先结束受保护的 Claude/Code/已识别辅助进程。
2. 确认退出，清理本工具的规则并核验 state。
3. 释放本工具的 PF token，验证防护清理完成。临时 IPv6 保持当前选择；菜单栏“恢复并退出”才还原原设置。

允许规则使用 `no state`，不自动清空全局 state，不全局禁用 PF。未知既有 state 或外部规则冲突可能导致拒绝启动。无法证明恢复完成时保留恢复资产并显示“恢复受阻”。关闭主窗口只隐藏 UI；菜单栏与心跳继续运行。重启不会自动启动 Claude 或进入防护模式。

### IP、IPv6 和隐私

界面自动 IP 检测是信息展示；Daemon 的安全验收独立执行。无在线地理定位，不把“固定 IPv4”写成已验证的国家/地区。IPv6 没有实际测试路径时显示未完成实包验证，不宣称实测通过。

无遥测、无自动日志上传。探针会访问外部检测服务，详情见 [NOTICE.md](NOTICE.md)。反馈报告可能含地址、时间和进程信息，应自行脱敏。

## 紧急恢复

优先点击“关闭防护”。恢复工具已内置：App 点击「恢复工具」会同时打开手册与文件夹。App 无响应/已删除时，重新打开 DMG 的安装器，选择「恢复工具」，无需安装。双击文件夹内「恢复网络.command」，先选 2、仍断网才选 3。以下是该文件夹中的终端备选：

```bash
/bin/bash ./scripts/emergency-recover.sh --force-own
```

此命令停止助手并清除本工具 filter，保留 token、state 和事务记录；**不是完整 OFF 验收**，不要立即再启动 Claude。若仍断网，才使用：

```bash
/bin/bash ./scripts/emergency-recover.sh --last-resort
```

后者全局禁用 PF，可能影响其他软件防护。若临时 IPv6 尚未恢复，在助手已停止、工具 filter 已清除后执行：

```bash
sudo '/Library/PrivilegedHelperTools/local.claudesafelauncher.guard' --restore-ipv6
```

仍无法恢复时重启并保留日志。重启能恢复连接不等于所有持久设置已核验恢复。不要删除未知事务记录来强行安装。

## 卸载、问题反馈与当前状态

先打开 App「恢复工具」内的「移除 Claude Guard」，在执行前通过菜单栏恢复并退出，确认 Claude/Code 已退出、原 IPv6 已恢复；直接拖走 App 不会移除 root 助手。先完成恢复再卸载。

本版经过离线逻辑、恢复/安装模拟和构建检查；PF 实机、真实代理与应用行为仍需按手册验收。已有本机旧版本记录不等于所有 Mac 或代理软件通过。最新公开版改变了核心登记和初次配置，需要重新验收。

反馈建议包含：macOS/应用版本、点击时刻、操作、期望/实际表现、导出的脱敏报告、是否完成 OFF/恢复。不要提交代理密码、完整私有配置或本机历史日志。项目仓库：[colorful-tju/Claude-Guard](https://github.com/colorful-tju/Claude-Guard)。问题请通过 Issues 提交。

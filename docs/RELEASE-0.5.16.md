# 0.5.16 测试版：进程采集短暂失败不再立即关闭 Claude

版本 0.5.16+43，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证；Intel 尚未真机验收。

## 修复内容

- 运行中的状态查询与重新检测请求读取监控结果，不再因一次全系统进程枚举失败直接结束 Claude。
- 启动门禁与持续防护门禁分开。首次启动、启动最终快照和解除 PF 前仍要求完整进程清单；绝不将不完整清单改写成完整。
- 每秒监控允许最多 5 秒的进程信息复核窗口。异步出口结果需要重验本地环境时也使用同一窗口，不另开计时。
- 复核期间 PF、规则/引用/state、核心签名及网关连接、TUN/接口/路由、心跳和睡眠检查照常执行；核心本身无法核验、保护条件失效仍立即进入停止流程。
- 完整采集恢复后立即清零窗口；持续无法确认则保守停止。结束 Claude 后仍不能证明完整退出时保留限制，显示恢复受阻，不虚报 OFF。
- UI 用黄色显示「进程信息复核中，PF 防护保持运行」，Claude 未知状态不再冒充未运行。
- 新增结构化失败字段和 `last-monitoring-degradation.json`，记录复核时长、次数、原生重试、失败 PID、是否已追踪、恢复后的名称/启动时间，以及退出或 PID 复用。没有旧身份时不臆测 exec 或 PID 复用。事件日志同时保留开始、恢复或超时记录；反馈不包含代理密码。

## 保持不变

运行时确实检测到不同公网 IP 仍立即停止；出口服务不可用仍按 0.5.15 的五分钟重测/提醒策略处理。PF allowlist 与解除前核验不变。未增加新的网络直连例外，不自动切换代理、节点、TUN 或 DNS。

本版并不保证任意异常下 Claude 都继续运行。5 秒窗口内仍无法确认进程清单会停止，且不可读取代理核心不属于可容忍的无关进程问题。监控是周期性的，不声称每秒采样等于内核原子快照。

## 手动验证

1. 记下节点和登记核心配置；从旧版菜单栏「恢复并退出」，确认 OFF。按 DMG 说明卸载旧版再安装新版，卸载会清空设置。
2. 手动准备原有代理/TUN、端点与 IPv6 条件。先「仅验证防护」，确认 ARMED，再正常关闭防护确认 OFF 与网页可用。
3. 安全启动 Claude，正常使用至少 30 分钟，包括 Claude Code 命令、子进程和模拟器等原来容易触发的任务。不要刻意改路由或停止代理来制造进程错误。
4. 若自然发生短暂采集异常，预期黄色复核提示，Claude 继续工作，恢复后返回正常。没有遇到该异常不能算作真实复核分支验收通过；该分支已有离线注入测试。
5. 导出反馈并附启动、异常、恢复时间与 Claude 是否被结束。若停机，另运行只读采集以保留 `last-monitoring-degradation.json`。该文件可能属于上一次降级事件，以 sessionID 和 capturedAt 为准。
6. 点击「关闭防护」，预期先结束 Claude/Code，再清理本工具限制。若进程清单持续不可读，允许显示恢复受阻，不能强行宣称退出完成。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；选项 3 可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

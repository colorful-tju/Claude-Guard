# 0.5.34 测试版：修复隔离 Core 配置加载

## 已确认原因

此前两个候选都在配置加载阶段收到 `config_rejected: default nameserver should have at least one nameserver`，没有进入代理连接测试。应用把此错误归为 IPC reply rejected，再呈现为没有候选通过。不能据此判断候选不可用或发生 IP 泄露。

## 修复

- 临时配置保持 DNS 禁用、无 DNS 监听、无系统 DNS 或公网 bootstrap；仅使用 `127.0.0.1:1` 的回环占位满足 Core 的非空字段校验。代理入口仍固定数字 IP，目标域名由代理协议携带，不能把该占位改成公网解析器来规避错误。
- 已知配置拒绝错误显示具体原因；其他配置拒绝显示固定错误类别，不输出凭据或原始配置。
- 包含本地诊断版的逐候选阶段记录、反馈导出、结果保留及相同设置值不取消验证的修复。
- 不改 FLClash 配置、节点、TUN、系统 DNS、PF 授权或现有防护门禁。

## 验证范围

提供 `scripts/test-entry-core-offline.py --core /path/to/FlClashCore` 集成测试：普通用户临时副本、合成节点、私有 FIFO/IPC、沙盒禁止全部 IP 网络；完整旧配置必须复现错误，完整新配置必须成功加载。未调用公网探针，也没有连接活动 Core。

这证明本次配置加载错误已修复，不等于真实节点握手与出口已通过。版本仍属预发布。

## 安装与复测

关闭防护、退出旧 App 后按 DMG 说明安装。确认版本 0.5.34，保持你当前已准备的 FLClash 节点和网络模式，读取当前链路，再点“验证前置连接”。

本次预期能够越过“隔离配置传输与加载”，进入“代理协议与 HTTPS 回显”。只有唯一候选通过所有验证才会填入；不要手动猜选。无论结果如何，请导出桌面 `ClaudeGuard反馈.json`，用于确认真实协议测试及入口选择结果。

兜底：独立测试不改变 PF/路由，卡住先取消。若后续正式防护测试影响网络，使用包内恢复工具，优先正常恢复，模式 3 仅最后兜底。

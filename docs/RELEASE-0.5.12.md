# 0.5.12 测试版：补齐启动验证与启动边界

版本 0.5.12+39，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证，Intel 尚未真机验收。

## 问题与修复

0.5.11 修复了 ARMED 运行中的路由重核验，但启动探针期间仅 epoch 变化仍会拒绝。本版补齐启动事务，不跳过最终快照检查。

- PF 加载后、探针开始前：仅 epoch 增加且其余证据完全一致，可建立新的首轮探针基线。
- 首轮全部探针结束：如果首轮证据有效且最终快照仅 epoch 增加，保持 PF，最多重新执行一次完整 TCP/UDP/STUN 与双 HTTPS 探针。不复用旧结果，不重载 PF。
- 第二轮仍变化：拒绝并恢复，中文提示网络持续变化。接口身份、路径、PF、核心或进程条件变化不进入重试。
- Claude 签名核验移到最终快照前。完成 ARMED 后、实际启动前及启动返回后的普通通知，使用与运行中相同的完整本地重核验；不是凭出口 IP 放行。
- 启动诊断新增 attempt、networkEvents；启动失败后的反馈也记录路由事件，不再只保留 epoch。

## 回归边界

测试覆盖首轮路由事件、应用签名检查期间事件、PF 安装期间纯代次变化、启动边界事件、第二轮继续变化、旧结果重用、无效首轮证据、真实接口/路径变化、用户取消与恢复。首轮回归先在旧代码中失败，再验证修复。

未放宽 PF、出口、身份、未知事件与恢复约束。采集过程中仍无法形成一致快照、持续变化或探针失败会拒绝；不是承诺任何环境都不停止。启动两轮均受现有命令超时、心跳与 90 秒 IPC 等边界约束。

## 手动验证与反馈

1. 保存配置，旧版恢复并退出确认 OFF，按 DMG 提示卸载并安装；卸载会清空配置。
2. 由你手动准备原代理/TUN及 IPv6 设置，在公司 Wi-Fi 点击「仅验证防护」。若只有通知变化，允许显示重新完整验证（2/2），成功后进入 ARMED；最多两轮。
3. 确认 https://api.ipify.org/ 与 https://ipv4.webshare.io/ 返回预期出口。正常关闭防护，再安全启动 Claude，进行日常对话与 Code 工作。不必主动改路由或切换节点。
4. 关闭防护确认 OFF、网页可用。导出反馈，附点击时间、是否看到重试、是否启动成功；如果失败直接导出，不反复尝试。

本轮构建与自动测试不安装助手、不启用 PF、不切换网络。实机保护仍由用户手动验收。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

# 0.5.25 测试版：修复启动超时后的防护回滚

版本 0.5.25+52；macOS 14+，Apple Silicon / Intel。个人测试版，临时签名、未获 Apple 公证；Intel 未真机验收。

## 修复

此前系统打开应用的命令超时后，程序会结束当时可见的 Claude，再移除 PF；但超时不代表系统取消了启动请求，Claude 可能在恢复 OFF 后才出现。

现在提交请求前先持久化“启动结果待确认”。启动等待预算从 5 秒改为 30 秒；命令成功后还必须读取到安装用户下精确路径的 Claude 主进程，并复读确认身份。启动后的本地前提核验和确认记录写入成功，才清除此标记。

超时、取消、未观测到主进程、确认写入失败等情况下，保持 PF 和事务记录，显示“Claude 启动请求结果未确认”。继续每 5 秒尝试结束迟到的 Claude，不受普通恢复三次主动重试上限影响；一次无进程或发信号成功都不能视为系统请求已取消。

## 启动出口策略

并发查询两个回显服务。至少一个返回有效预期 IPv4 即可通过；另一服务超时或网络错误不会单独阻止启动。任何已返回的有效 IP 与预期不一致仍拒绝；两者无有效结果也拒绝。探针执行器卡死或无法确认子任务结束仍属于内部错误，不作为普通服务超时放行。

PF 实包与计数验收、最终本地快照不变。“检测并填入出口 IP”仍要求两个服务一致，以免从单个异常结果误填设置。

## 验证方法

1. 保存工作，恢复 OFF 后按 DMG 说明更新。手动准备代理/TUN，先运行“仅验证防护”。
2. 安全启动 Claude，确认实际出现应用且启动器保持 ARMED。使用后点击“关闭防护”，确认正常恢复 OFF。
3. 若一个检测服务失败而另一个返回目标 IP，应能通过出口阶段。无需故意修改网络复现；遇到时导出反馈，日志会列出服务及结果。
4. 若再出现启动超时，应该显示“启动结果未确认 / 恢复受阻”，而不是 OFF。不要反复点击启动或手动启动 Claude；保留反馈，保存工作后重启，让旧启动请求和旧 PF 状态随内核重启结束。

## 限制与恢复

LaunchServices 没有在本工具中提供可验证的请求取消句柄。30 秒只是等待预算，不是取消证明。成功条件采用单次命令成功、主进程已被真实观测及最终本地核验；不声称实现系统级原子启动。主进程曾被确认、随后立即正常退出时，由常规监控完成退出恢复。未确认请求不能仅靠等待自动解除。

开发仅做离线模拟、错误注入和打包核验，没有操作用户的代理、TUN、PF 或 IPv6；真实故障场景仍需用户复测。

兜底：优先保存工作后重启。若必须即时恢复网络，可使用“恢复工具 → 恢复网络.command → 2”，按提示确认 `UNPROTECT_OWN`；这会解除本工具保护，系统尚未确认的请求仍可能启动 Claude，不属于正常 OFF。仍断网再选 3（可能停用整个 PF），按提示确认 `UNPROTECT`。请保留桌面恢复记录和反馈，不删除事务文件。

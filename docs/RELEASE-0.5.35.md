# 0.5.35 测试版：修复前置验证配置的斜杠转义

0.5.34 的 DNS 非空校验修复后，实际应用仍未进入代理握手。原因是 Swift JSONSerialization 默认把 WebSocket 路径的 `/` 写成 `\/`，Core 按 YAML 读取时返回 `yaml: found unknown escape character`。之前 Python 集成测试没有产生相同的字节，遗漏了这一差异。

- 配置传输统一由生产 `EntryProbeConfigPipe(config:)` 序列化，使用 `.withoutEscapingSlashes`；保留引号、反斜杠、Unicode 和认证值，不对整个文本做替换。
- 新增真实 Core 集成测试：使用生产 Swift 序列化及 FIFO 传输后的字节，在禁止全部 IP 网络的沙盒中加载；修复字节加载成功，旧转义字节必须复现原错误。
- 不修改活动 FLClash、订阅、节点、TUN、系统 DNS、PF、TLS 校验或防护放行范围。

## 验证与限制

普通回归验证私有管道、无凭据文件残留、字符串语义不变。显式设置 `CG_ENTRY_OFFLINE_CORE` 后，测试才执行复制 Core 的离线集成测试，仅发送初始化和配置加载，不发送公网探针。不等于实际机场连接或最终 ISP 出口已经验证；Intel 包仍需 Intel 实机验收。

## 复测

1. 关闭防护、退出旧 App，按 DMG 内说明安装，确认 **0.5.35+63**。
2. 保持你手动准备的 FLClash 链路，重新检测配置并点击“验证前置连接”。
3. 本次应越过“隔离配置传输与加载”，继续代理协议和 HTTPS 回显。若失败，导出反馈；不要根据未核验 IP 猜选入口。

兜底：前置独立验证不加载 PF 或更改路由。若后续正式防护影响网络，使用离线恢复工具，优先正常恢复，模式 3 仅作最后手段。

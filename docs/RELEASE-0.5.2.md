# Claude Guard 0.5.2 测试版

本轮针对外部审计修复：

- 卸载最后才删除助手，降低中途失败后失去恢复执行程序的风险。安装事务锁仍保留保守处理，不自动删除未知锁。
- 应急恢复等待事务锁最多 3 秒。常规兜底失败后，离线菜单提供二次输入 UNPROTECT 的全局 PF 停用选项；它可越过助手、进程、锁的核验失败，仅确认当时 PF 停用，不代表 OFF 验收，也不保证其他程序不会重新启用 PF。
- PF dry parse 明确要求最后一条为无接口限定的默认出站拒绝规则。
- 修复后台健康任务的 DispatchGroup 生命周期、收紧命令行操作白名单、拒绝多文档 YAML 和非规范 IPv4 节点。
- 修复合成验证器过时的错误文本断言，将其加入标准测试入口。
- 文档明确当前实际流程没有放行物理 DHCP 续租；没有将其作为已实现功能宣传。

没有放宽日常防护条件，没有修改代理选择和系统网络。未使用本轮构建执行实机 PF、真实卸载或真实泄漏验收。Intel 仍仅完成交叉构建与静态检查。

## 验证建议

更新前保存配置并正常关闭防护。更新后依次测试首次启动、仅验证防护、正常 OFF，再测试安全启动和退出。不要为了测试应急功能主动制造断网；本轮应急错误路径使用隔离命令替身验证。

兜底：安装器「恢复工具」→「恢复网络.command」→2；仍断网选择3。若核验受阻，可阅读提示后输入 UNPROTECT，解除整个 PF 防护。该操作影响其他防火墙；不要继续运行 Claude。仍无网络请重启 Mac 并保留终端输出。

软件仍为 ad-hoc 个人测试签名，未获 Apple 公证。签名完整性不等于发布者身份认证；请从本项目 Release 下载。

## 审计范围与保留项

逐进程观测依旧是辅助信号，PF 才是主要限制。未声称消除所有竞态或覆盖 VM/远程执行。未知安装锁和缺失助手不自动强行卸载：保留资产，并使用离线恢复后再处理。没有新增未验证的 DHCP 例外，也没有因审计建议而拒绝原本有效的策略组配置。技术文档按钮当前已指向实际资源，未重复修改。界面细节和无实际路径的重复校验不在本轮修复范围。

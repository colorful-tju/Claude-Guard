# 0.5.11 测试版：减少路由通知导致的非必要停止

版本 0.5.11+38，macOS 14+。Apple Silicon / Intel，临时签名、未公证；Intel 尚未真机验收。

## 本轮定位与修复

反馈中一条普通新增路由通知使 epoch 增加，原代码将它写入全部接口的 generation。虽然接口、关键路径、核心连接和 PF 证据不变，仍因 TUN 身份不匹配关闭 Claude。旧记录没有路由目标及 errno，不能认定该通知必然无害或属于失败请求。

现在分离事件 epoch 与接口生命周期。在 ARMED 中，普通路由事件后重新核验核心、接口、关键路由、PF 和 state；只有全部前提仍满足原基线才继续。PF 全程生效，不更新原基线、接口白名单或出口许可。异步出口检测返回时如事件代次改变，也进行本地重核验，不能仅凭正确出口放行。

普通路由请求返回正 errno 表示操作失败，记录诊断但不视作成功变更。诊断保留 errno、flags、pid、seq、地址位图及有界十六进制地址载荷。重定向、接口 down/up、地址变化、未知消息、读取失败继续保守停止。启动阶段、采集中持续变化仍不允许用重核验绕过严格条件。

## 停止条件代码审阅

- PF 规则/引用/state/anchor、Core 身份与连接：保持必须验证，未知证据不放行。
- UDP socket 观测：仍只作诊断，不因存在 UDP socket 就杀进程。
- 心跳：保留受保护阶段 30 秒窗口；实际 UI 退出和睡眠唤醒继续停止。
- 出口：不匹配立即停止；检测服务失败使用既有有限重试与 45 秒有效期，不无限延长。
- 普通 Claude 子进程增长、同核心网关 TCP 本地端口更新：保留已有兼容处理。
- 恢复：先终止 Claude、确认退出再撤自身 PF；手动 OFF 为正常操作。
- 仍可能保守停止：采集期间网络持续改变、未知事件、权限或进程身份无法验证。不能保证所有网络环境零误停；本轮不扩大未知状态的信任范围。

## 回归与人工验收

离线回归覆盖通知代次增加但本地证据一致、失败路由请求、接口生命周期变化、重定向/未知事件、PF/路径变化、启动阶段通知变化、出口回调期间通知变化。原来的错误关闭先由回归复现，再验证修复。

1. 保存配置，旧版恢复并退出确认 OFF；按照 DMG 提示卸载并安装，卸载会清空配置。
2. 手动准备原代理/TUN及 IPv6 设置，执行仅验证防护。确认 ARMED 后，两个出口网址 https://api.ipify.org/ 和 https://ipv4.webshare.io/ 应符合预期。
3. 再安全启动 Claude，使用公司 Wi-Fi 正常工作 30 分钟。不必主动制造路由变化；如果系统发出可重核验的通知，反馈应出现 `route notification revalidated`，且继续 ARMED。
4. 关闭防护，确认 Claude 退出、OFF、网页正常。导出反馈并给出开始/结束时间。若自动停止，直接导出记录，不反复重试。

本轮不自动切换代理、不运行真实泄漏探针、不安装助手或启用 PF。离线测试和包核验不替代实机验收。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

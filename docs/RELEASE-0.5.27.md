# 0.5.27 测试候选：独立 UDP 防护

本候选新增全机、无应用识别的 UDP 限制。链式完整防护尚未交付，不得将本功能视为加拿大 TCP 出口验证。

- 首页增加「开启 UDP 防护」，与完整 Claude 防护互斥。
- 独立模式不启动、查询、结束或等待 Claude；关闭按钮按当前会话类型恢复。
- IPv4/IPv6 出站 UDP 默认拒绝，保留回环及受限 DHCPv4。TCP 不添加放行/阻断规则。
- 开启需物理接口 DNS/STUN 负向探针失败且对应专用 PF 计数增加。IPv6 尚无实包验收。
- 不因 IP 检测服务超时或阻断次数增长关闭应用。
- 已存在 UDP/未知 state、活跃第三方 PF 规则等情况会拒绝开启，不自动清理他人状态。
- 正常停止核验自身规则及引用；已完成验证的 UDP 会话可在助手重启后恢复。若助手在提交 PF 或探针过程中崩溃、旧 worker 退出无法证明，则保留事务并提示独立恢复/重启，不虚报 OFF。

## 使用范围

适合 TCP 外层代理与 DoH。UDP 代理、传统 UDP DNS、部分游戏/音视频可能不可用。当前临时 IPv6 租约需先恢复，再开启本模式；此模式不修改 IPv6 系统设置。

完整 Claude 模式的恢复流程不变。运行时前置/落地链路验证仍待独立适配，因此链式用户只能把此候选作为 UDP 限制工具，不能据此宣称 TCP 全程经过指定 ISP。

## 人工验收

见应用内《完整验证手册》的「独立 UDP 防护验收」。构建及自动化测试不启停真实 PF，也不切换代理；需要用户手动完成真实网络验收。Intel 为交叉构建，未完成 Intel 实机验收。

兜底：优先点「关闭防护」；受阻时用「恢复工具 → 恢复网络.command」选 2，只解除自身规则；仍断网再选 3（影响整个 PF）。仍失败重启，保留反馈，勿手动删除事务文件。

# 0.5.27 测试版（build 55）：独立 UDP 防护与固定链式入口

## 完整防护：直连 / 链式

网络设置新增路径选择。直连模式保留原有单节点 HTTP 流程；链式模式将物理入口与最终 HTTP ISP 分离。PF 仍仅放行一个用户确认的前置公网 IPv4/TCP 端口，其他物理出站、新接口和非授权 UDP/IPv6 继续默认拒绝。

- 前置支持配置内的 TCP 节点及手动 select，拒绝 UDP 外层、插件、继续嵌套链路及自动选路；不自动跟随入口地址变化。
- “读取前置连接”仅显示已登记 Core 在物理接口上建立的同端口连接。域名前置需要用户核对当前 IPv4；多个候选不能区分时不要猜选。不会改写域名或修改代理配置。
- 启动仍需真实前置连接、TUN/签名/PF/state 核验、至少一个匹配出口且无冲突返回、绑定物理接口的负向探针及计数增加、最终快照。
- 已 ARMED 的链式会话中，明确无上游连接只表示空闲或断网，保留 PF，不因此单独关闭 Claude。出口检测失败每 5 分钟重测并提醒；有效出口不匹配仍停止。Core/TUN/接口/PF 等关键证据失效仍处理。
- 不开启控制 API，不宣称每条请求的内层代理链被逐跳观察。完整防护的 Claude 退出和延迟启动恢复机制不变。

## 独立 UDP 防护

- 首页新增“开启 UDP 防护”，与完整防护在 UI 和 daemon 两层互斥。
- 全机无应用识别：IPv4/IPv6 非回环出站 UDP 默认拒绝，保留受限 DHCPv4。不开启、查询、结束或等待 Claude。不限制 TCP、不保证加拿大出口。
- 关闭按钮按当前会话恢复。开始前拒绝可能绕过规则的既有 UDP/未知 state，不清其他软件的状态。
- 完成验证的会话在助手重启后执行恢复；在提交 PF 或探针中崩溃且无法证明旧 worker 退出时，保留资产，要求明确恢复或重启，不虚报 OFF。

## 使用与验证范围

此版适合固定 TCP 前置、HTTP ISP、DoH。仅 UDP 模式可能阻断传统 DNS、UDP 代理、游戏或音视频。已有临时 IPv6 租约需先恢复，再启用独立 UDP；该模式不修改系统 IPv6。

自动化覆盖为离线逻辑、模拟事务、恢复和打包。未在开发过程中启停真实 PF、切换代理或安装助手；新模式需用户手动完成应用内《完整验证手册》的验收。IPv6 无实包路径时不宣称已实测。Intel 包仅交叉构建和静态校验，未完成 Intel 实机验收。

兜底顺序：先“关闭防护”；受阻时“恢复工具 → 恢复网络.command”选 2（自身规则）；仍断网再选 3（影响整个 PF）；仍失败重启。保留反馈，不手动删除事务文件。

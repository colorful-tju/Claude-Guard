# 0.5.21 测试版：配置数量预览与 PF 冲突诊断

版本 0.5.21+48，macOS 14+；提供 Apple Silicon 和 Intel 包。临时签名、未获 Apple 公证；Intel 未真机验收。

## 配置选择

网络设置 → 读取 FLClash 配置：每个 YAML 显示配置内节点数、HTTP 节点数。即使订阅名称不可读、文件名全是数字，也可以先区分单节点与多节点配置。

统计只读取文件内 `proxies`，不会下载 `proxy-providers`；存在外部来源时标注数量和“总数未知”。读取失败、语法不支持或超出限额显示“未能预览”，不会误报 0 个节点。预览只辅助选择，登记和启动时仍独立核验，不会自动登记、切换代理或修改配置。

## 失败诊断

- `Unknown PF root anchor` 现在保留当时实际读取的名称；未知 Apple 子分支也记录名称。
- 对 `com.apple.internet-sharing` 给出中文兼容性提示，避免误以为是 YAML 或出口 IP 错误。
- PF 失败弹窗给出具体原因和处理步骤，支持复制只读诊断命令；主界面“处理方法”可再次打开，状态刷新不重复弹窗。区分活跃共享规则、读取失败和检查期间规则变化，不把它们统称为泄漏。
- 只读 PF 采集工具补充互联网共享及 `host_v4` / `host_v6` 的实际规则。

**精确兼容服务停止后的空共享分支，不允许活跃共享规则。** 停止服务后，macOS 可能仍保留 `com.apple.internet-sharing` 及 `host_v4` / `host_v6` 名称。本版要求 root 过滤/NAT 内容均空、子分支只限这两个已知名称、子分支过滤/NAT/后代均空，并检查主规则入口格式及现有 state。任一读取失败、活跃规则或未知后代仍拒绝。结构纳入前提指纹，运行中持续复查；OFF 不删除这些其他软件留下的空分支。

本版没有自动停用虚拟机。系统共享/虚拟机创建的桥接、IPv6 和 `keep state` 规则仍与当前严格防护不兼容。用户需先保存工作，通过相应软件正常停用网络服务，再重新验证。不能只删除这些 PF 规则，也不等于已经发现 IP 泄漏。

## 验证与恢复

1. 按 DMG 说明更新，保持 OFF，读取配置列表，检查单节点、多节点和外部来源提示；取消应保留原登记。
2. 选择单节点 HTTP 配置并登记，核对网关/端口和预期出口，再确认端点。
3. 若出现共享网络不兼容，先停止相关虚拟机/共享服务，重新只读查询 PF 环境；不要清空系统规则。需要与虚拟机并行运行时，当前版本尚未提供兼容保证。
4. 用户手动准备代理和 TUN，先“仅验证防护”，通过后再启动 Claude。离线回归及包校验不替代实机验收。

兜底：安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**（可能停用整个 PF，影响其他防火墙）；受阻按说明确认 `UNPROTECT`。仍无法联网请重启并保留输出。

# Claude Guard 0.5.3 · 长时间运行误停修复

## 定位结论

反馈会话在约 49 分钟后停止。详细快照显示：实际物理接口、TUN 名称/索引/IPv4、代理 Core 和已建立网关连接、PF 规则及 state 均未改变；awdl0 与 llw0 的 IPv6 链路本地地址发生变化。旧版把全局路由事件计数同时用作每个接口的 generation，因此产生了误导性的 TUN 身份差异。该记录不证明发生过 IP 泄漏；事发时 PF 仍启用，随后完成正常 OFF 恢复。

## 修复边界

- 路由事件解码保留关联接口索引，验证消息长度和版本。
- 仅已明确归属 awdl0/llw0 的事件不使全局计数失效；它们不能作为当前策略允许的物理 enN 或 utunN 接口。未知归属不会忽略。
- 仅运行期允许这两个接口合法 IPv6 链路本地地址轮换。索引、标志、IPv4、全局 IPv6、其他接口及实际路由变化仍保留检查。
- 启动前快照和探针一致性不放宽，不自动变更 PF allowlist。
- 通用运行态证据不足提示不再直接暗示已确认 TUN 变动。

未修改代理、节点、DNS 或当前 PF；未执行真实泄漏探针。自动化回归不代替长时间实机验证。Intel 为交叉构建，软件仍未获 Developer ID 签名或 Apple 公证。

## 手动验证与反馈

1. 在旧版正常关闭防护并恢复退出，再安装对应芯片的新版；确认版本为 0.5.3+29。
2. 由用户自行准备原代理/TUN，核对端点、出口和 IPv6 状态。先执行「仅验证防护」，确认 ARMED 与两个 IP 测试正常，再正常关闭。
3. 安全启动 Claude，正常使用 60–90 分钟；不要主动切换代理或 TUN。偶尔检查仍为 ARMED，测试网页和 Claude/Code 是否正常。
4. 结束时点「关闭防护」，确认 Claude 退出并恢复 OFF。导出反馈，记录开始、结束、异常时刻和版本。
5. 若再自动停止，请保留反馈和详细故障快照；仅前后均没有发生辅助接口地址轮换时，长时间未停不足以证明本问题已经实机覆盖。

## 每轮测试的恢复兜底

安装器 → 恢复工具 → 恢复网络.command，先选 2；仍断网选 3。若常规兜底核验受阻，阅读风险后输入 UNPROTECT 可解除整个 PF，影响其他防火墙，且不保证其他软件不会重新启用 PF。不要继续运行 Claude；仍无法联网请重启 Mac，并保存终端输出。

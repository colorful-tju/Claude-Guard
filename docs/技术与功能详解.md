# Claude Guard 技术与功能详解

版本：0.5.17+44（测试版）。适用 Apple Silicon / Intel、macOS 14+；Intel 尚未完成真机验收。作者 colorful / colorful-tju。本项目源码可见，禁止商用与二次开发；不是 Anthropic 官方产品。

## 1. 用途与支持范围

工具在用户已经准备好的 HTTP/TCP 数字 IPv4 代理及 TUN 上增加临时 PF 出口约束。重点阻止绑定物理接口的 UDP、DNS、STUN 旁路，不提供代理服务，也不替用户切换代理或 DNS。

当前支持单节点 Mihomo/Clash HTTP YAML、服务商确认的数字 endpoint，以及能够核验 TUN/socket 归属的登记核心。不支持域名 endpoint、UDP 隧道、多节点 provider 或任意 VPN。相同出口 IP 不能代替核心身份和路径验证。默认拒绝会影响整机其他应用的新出站流量。

## 2. 组件与权限

- SwiftUI App：普通用户运行，管理网络参数、状态展示、心跳、提示及文档入口。
- root GuardDaemon：持有安全事务，检查核心、进程、网络与 PF；执行有序停止和恢复。通过 launchd 管理。
- guard-probe：独立受限探针进程，执行出口和物理接口负向验证；子进程有截止时间与取消机制。
- IPC：检查连接对端 audit token、UID、安装时登记的代码身份与协议版本。本版本协议为 8，更新须匹配 App 和助手。

管理员授权用于安装/更新/移除助手；正常操作由已授权助手完成，不让 UI 以 root 运行。不要求 Network Extension entitlement，不关闭 SIP。仅采用 ad-hoc 签名，尚无 Developer ID 公证，不能视为已完成公开发行认证。

## 3. 网络数据模型

Gateway IPv4/port 是代理连接入口；expected egress IPv4 是外部网站看见的出口，两者独立。IP 检测只能填写预期出口，不能推出 gateway 或端口。用户从服务商核对数字 endpoint 后点击「确认代理端点」。重新检测或编辑相关参数使确认失效；重启不自动恢复确认或防护。

安装登记核心可执行文件和配置路径。运行验证包括配置指纹、协议、真实已建立 gateway TCP socket、核心持有的 TUN、路由及探针。节点名字和 GUI 是否存在不是安全依据。

## 4. 防护事务

OFF → 检查/验证 → ARMED → 停止中 → OFF；无法证明清理完成时进入恢复受阻。

启动前要求受保护进程退出。核验 PF 环境、规则执行入口和已有 state 后，加载独立 Apple 分发子 anchor。仅授权 lo0、已验证 TUN、指定物理接口到 gateway 的 TCP，其余新出站 IP 流量默认拒绝，不统放 utun*，新增接口也不自动放行。

允许规则为 no state；不清空全局 state。无法分类或不符合授权路径的已有 state 会拒绝启动。规则、引用、状态在事务阶段核验，移除时只处理自身资源。

两个独立 HTTPS 回显服务须返回预期 IPv4；物理接口 TCP、UDP/STUN 负向探针须失败且专用 block 计数增加。仅超时或规则可见不能通过。最后再次核对接口、路由、核心连接、配置、PF 与进程前提，才进入 ARMED。该快照不是跨内核子系统的原子操作；PF 持续提供默认拒绝。

## 5. 监控与 Claude Code

本地关键条件约每秒检查，出口周期复核。Claude Code 的可识别子进程纳入生命周期管理；普通 UDP socket 的存在不等同于泄漏，不因此单独杀进程。PF 是先行边界，socket 观测只是有限诊断，未知流量不得归因给 Claude。

无法维持关键条件时停止受保护进程，记录差异并给中文提示。并不等待已确认泄漏后才阻断。不能保证覆盖远程运行器、虚拟机、特权绕过或所有脱离追踪的后代。不存在“所有设备信息不可见”的承诺。

## 6. 手动关闭、退出与 IPv6

点击「关闭防护」无需先退出 Claude：保持 PF → 结束 Claude/Code 及已识别辅助进程 → 确认退出 → 核验/移除自身规则与 state → 释放自身引用 → OFF。正常操作不显示自动阻断弹窗；如果进程无法结束或清理失败，仍报告恢复受阻，不能隐藏真实风险。

手动停止请求可打断等待中的探针。监控队列遇到该请求时执行正常停止，不将取消异常记录为自动风险。正常停止完成后清除旧中断提示。

IPv6 是独立临时租约：OFF 且 Claude/Code 已退出时可临时关闭、启用 Automatic 或恢复原值；普通关闭防护、仅验证结束后保持用户选择。界面仍开着时租约心跳继续。菜单栏「恢复并退出」使用完整 shutdown，先结束受保护进程和 PF 事务，再还原原 IPv6；UI 心跳丢失/崩溃由助手执行恢复。关闭主窗口只是隐藏，不等于退出。Automatic 不一定等于修改前状态，恢复原设置使用快照。

## 7. 界面与反馈

三色横幅区分运行、等待和异常；执行框显示步骤与中文处理建议。网络设置提供 endpoint 确认按钮；IP 面板显示检测结果与预期值；菜单栏提供状态和退出入口。

「恢复工具」同时打开内置文件夹和恢复手册；「查看测试手册」打开完整验收；软件声明页可打开本文。反馈报告保存在用户选择位置，无自动上传。报告可能含地址、接口与进程信息，提交前须脱敏。探针依赖外部检测站点，无离线出口认证或在线国家认证。

## 8. 交付、资源与恢复

DMG 仅显示「双击安装 Claude Guard.app」，无需拖拽。安装器提供恢复入口，App 删除/无法启动时也可从 DMG 打开，不必重新安装。应用内部 Contents/Resources/Recovery 包含恢复命令、手册、独立助手副本与移除工具；资源在最终签名前封装。

恢复正常路径先终止受保护应用，再处理自身 PF 和 IPv6。强制恢复选项 2 仅清自身 filter 并停止助手，保留 state/token/事务，不代表 OFF 验收；选项 3 会全局停用 PF，影响其他防火墙，只作最后兜底。恢复受阻不要删除事务记录强行重装。

## 9. 验证边界

离线测试覆盖取消竞态、手动停止顺序、清理失败、IPv6 租约、协议与安装恢复模拟；包检查核对签名、资源与架构。这些不能代替实机 PF、代理和 Claude 工作流验收。请按完整验证手册记录版本、时间、状态、网页结果、临时 IPv6 与退出恢复结果。本版仍为测试版。

## 10. 完整卸载

0.5.2 移除工具明确传递发起者 UID，以普通用户身份清除标准与 currentHost 偏好，检查启动器已退出，复读验证域不存在后才删除系统资产。不能用 root 的 defaults 代替用户偏好清理。历史版本仅删除 App/助手，未覆盖用户偏好；新卸载器清理失败会保留资产。手动导出的反馈与下载文件由用户自行管理。

历史版本实机复现：defaults 删除返回 0，但新进程仍读到旧值。清理流程加入精确 plist 清理，仅接受当前用户拥有的普通文件，拒绝符号链接；之后复读，仍存在则失败。普通目录、其他应用偏好和偏好守护进程均不操作。

## 0.5.2 双架构与一键出口检测

按芯片选择 AppleSilicon-arm64 或 Intel-x86_64 DMG；不匹配的安装包会拒绝安装。Intel 为交叉构建，须单独完成真机验收。网络设置点击「检测并填入出口 IP」后，两个服务一致才自动填写预期出口，网关和端口不变。检测失败、不一致或期间修改配置时应不覆盖旧值。该检测不启动 PF，也不证明防护已生效。

## 0.5.2 个人测试安装信任边界

包仍为ad-hoc签名，签名完整不等于Apple认可。安装器显式告知未公证，并通过仅本次命令环境标记确认用户选择。解包副本先验签，再仅移除com.apple.quarantine，再验签；无全局spctl/SIP更改。--self-test-timer在停止旧服务前检查新助手能否执行，正式--assert-off仍在取得互斥安全条件后运行。此流程只服务于明确接受来源的个人测试，不构成公证发行保证。

安全会话当前不开放物理接口 DHCP 续租；租约或接口变化可能触发安全停止。模型中的 DHCP 选项尚未接入运行流程。

0.5.3：路由事件读取保留事件所属接口索引。仅 awdl0/llw0 的已归属事件不推进全局失效计数；它们不能被当前策略选作 enN 物理出口或 utunN 隧道。运行期路由等价比较仅忽略这两个接口的合法带 scope IPv6 链路本地地址，保留索引、标志、其他地址和全部实际出口路径检查。启动验证仍严格比较；未知事件、丢失事件或受保护接口事件仍失效。此修复不放行辅助接口流量。

0.5.4 本地验证构建：socket 完整列表读取失败后最多重新采集三次，间隔 25ms；每次要求同一进程身份，成功样本不拼接、不使用缓存。持续失败仍停止会话，日志包含 PID、尝试次数和原生返回值/errno。恢复重试确认进程全部退出后更新异常事件的退出确认状态。


## 0.5.5：高负载心跳与阻断统计

心跳由独立串行后台队列每秒发送，不依赖主界面 Timer 或 MainActor 完成回调。防护/临时 IPv6 会话持有防 App Nap 活动令牌，不阻止电脑主动睡眠；睡眠/唤醒仍按原策略停止。

启动前与探针验证期间仍要求 6 秒内的新鲜心跳；完成启动后，ARMED 的心跳硬截止为 30 秒。6 秒开始显示黄色延迟提示，期间守护进程继续核验进程身份、PF、网络与出口，不删除规则。实际 UI 退出/身份变化、PF 或网络前提异常仍停止，不等待心跳宽限。宽限不是实时调度保证：持续系统过载、其他检测超时仍可能触发保守关闭。

单次后台心跳失败会重试；状态读取超时仅使 UI 不再显示绿色，不由界面猜测故障后主动发送 OFF。守护进程仍拥有最终停止权。显式启动/关闭命令的失败处理不变。导出反馈新增 UI 心跳尝试/失败数、最近通信耗时与调度延迟，以及守护进程心跳年龄、最大间隔和监控间隔；不据此推断 CPU 满载或 IP 泄漏。

顶部「已阻断数据包」来自本工具独占 anchor 的 5 条 block 规则的 PF packet counter，使用最终启动快照中的计数作为基线。统计整机、本会话采样后的增量，不包含启动自检及之前流量；不包含 pass 规则，既有系统/其他软件规则的计数也不混入。重传可能多次计数，无法归属具体进程，不是恶意请求数。读取失败显示暂不可用；计数回退使本会话统计失效，不重新归零掩盖问题。统计失败本身不结束防护，核心 PF 规则/引用/state 校验仍为独立硬条件。OFF 显示最后样本而非持续统计；下次会话重新开始。

## 0.5.6：有界出口复核

周期仍为 15 秒，并发查询两个固定 HTTPS 回显服务。任一合法公网 IPv4 与预期不同优先判定失败，包括另一服务正确、错误样本较旧的情况。无冲突且至少一个正确样本完成不超过 10 秒时通过；最后核验时间取样本完成的单调时钟，不取队列回调时间。

无有效证据时至少间隔 2 秒复检，连续 3 次失败或最后有效证据距今 45 秒停止，取先达到者；挂起请求也受监控循环的 45 秒截止约束。PF、身份、接口、路由及心跳核验不宽限。启动验证条件不变。用户态进程完全得不到调度时不能保证精确到秒执行，既有 PF 仍提供阻断。

`periodicEgress` 记录逐服务样本、错误、耗时、完成时间、队列延迟、原证据年龄、失败次数和决策，并写入事件日志。时间为单调时钟秒数，事件日志提供墙钟时间；不保存网页正文或代理密码。curl 失败保留退出码，不能由超时推断真实出口泄漏。UI 复检阶段黄色，PF 验证状态与出口新鲜度分开。

## 0.5.7：复检退避与固定错误特征

覆盖上节的 2 秒重试间隔：第一轮失败后等待 6 秒，第二轮后等待 10 秒，再调度复检。时钟使用单调时间，45 秒证据截止独立于调度；即使尚未到下一次复检时间，也必须停止过期会话。最多仍为连续 3 轮失败。检测成功后失败次数归零，回到 15 秒周期。PF/本地前提检查未改变。

curl stderr 仅扫描前 4096 字符，通过固定字符串匹配映射为有限错误标签，不回传原文。标签用于定位握手失败/重置/EOF，不用于放宽安全判断。`periodicEgress.retryAfterSeconds` 仅在计划重试时存在，`proofRemainingSeconds` 为处理报告时距最后有效证据 45 秒截止的剩余量；不是实时倒计时。旧版报告可没有这些字段。

## 0.5.8：启动错误传递

启动并发收集用 do/catch 记录两个服务的结果。已知 EchoRequestFailure 保存固定脱敏错误特征；命令错误只保留期限/取消/执行失败类别，未知异常不输出原文。失败时子进程以非零退出并通过独立 JSON 错误结构传递摘要；父进程只在 dual-https 非零退出时读取该结构，不把部分成功证据当作通过。超时报告包含当时仍 pending 的服务，子进程退出和外层有界清理维持原有行为。启动双服务、PF 和截止条件不变。

## 0.5.9 网络事件分类

PF_ROUTE socket 先打开，再以 NET_RT_IFLIST 只读快照建立 IFINFO 语义基线；初始化失败时不抑制通知。按接口索引比较 flags 和 if_data 的非统计字段（保留 lastchange、MTU、类型等）。仅统计计数变化或精确重复的 IFINFO 不递增安全失效 epoch。地址、路由变更以及未知类型保持保守失效；地址事件同时清除该接口的语义缓存。连续 down/up 即使最终快照恢复，仍会递增 epoch。既有 awdl0/llw0 处理保持原边界。

这里的 epoch 是全局安全失效代次，不是接口真实生命周期标识。实际接口索引、地址、路由、核心归属与 PF 仍通过完整快照独立检查。没有削弱最终快照检查，没有修改防火墙规则或允许新的接口。事件读取异常继续拒绝核验。最近 32 条相关事件存入故障诊断 networkEvents；签名只含接口状态，不含流量内容或代理凭据。未知通知仍可能触发保守停止。

普通 UI 导出的反馈中，事件出现在 report 的 `network-event` 行；助手完整诊断同时保留结构化 `networkEvents` 数组。

## 0.5.10 删除后存活进程兼容

仅 proc_pidpath 返回 ENOENT 时，核验可执行、已取消链接的常规文件内核映射；要求唯一 vnode/path、内核进程名匹配及二次 BSD 身份一致。扫描有上限，权限错误、歧义、身份变化仍失败。保留原路径参与 Claude/Helper 分类，不以命令行参数代替身份。

## 0.5.11 运行期路由通知重核验

网络通知 epoch 仍用于采集事务与启动前一致性检查。接口 generation 独立记录接口/地址/未知事件，不随普通 RTM_ADD/DELETE/CHANGE 更新。仅 ARMED 阶段可将完成一致性采集的当前快照与原基线重核验：完整路径指纹一致或通过既有窄范围路由等价证明，且 MonitoringGate 的全部其他条件通过，才在比较副本中归一化 epoch。不可修改原基线、PF、接口 allowlist 或出口时限。重定向和未知事件继续使接口身份代次失效。失败的普通路由请求（正 errno）记入诊断而不当作成功变化。

## 0.5.12 启动事务补齐

SafetySession 显式提供一次 retryValidation：必须先核验首轮探针在原基线上的有效性，再确认新快照仅 epoch 单调增加，完整核验本地前提后重建探针基线与时间。旧结果不能重新标注代次或用于 ARMED。PF 加载后尚未执行探针时，允许同样的纯 epoch 变化建立首轮基线。应用签名核验提前到最终快照之前；已完成 ARMED 验证后的启动边界通知沿用运行期全量本地核验。读取期间发生变化、未知/接口生命周期事件、路径或 PF 变化仍拒绝。失败诊断保留路由事件，轮次最多 2。

## 0.5.13 路由接口归属修正

RTM_ADD/DELETE/CHANGE 在 rtm_index 为 0 时，仅对完整的 IPv6 链路本地 host/prefix 消息，从 AF_LINK gateway 推导接口；要求目标 scope 与 gateway、IFP、IFA 一致，掩码不超出链路本地范围。仅实际名称 awdl0/llw0 沿用辅助接口事件分类。其他接口仍触发原有核验，不新增 PF 放行。解析失败保持 unknown；重定向不推导。日志保留 headerIndex，并将采集失败区分为 Core 身份变化或 epoch 前后值。

## 0.5.14 出口重试预算

重试等待为 min(原 6/10 秒等待, max(0, 45 秒证明期限剩余值 - 10 秒请求预算 - 2 秒调度余量))。请求执行与预算计算共用 EgressTiming.requestTimeout。当前 callback 的单调时钟时间用于计算，已发生的排队延迟不会重新获得预算；不能保证严重调度延迟下完成。硬期限与错误出口立即停止不变，日志继续记录实际 retryAfterSeconds 和 proofRemainingSeconds。

## 0.5.15 当前出口策略（替代历史 45 秒/三次失败规则）

首次启动仍要求双 HTTPS 核验。运行中任一服务返回非预期公网 IPv4 优先停止；无结果或陈旧结果每 300 秒重测，第二次失败产生独立 EgressWarning，持续同一故障不重复弹窗，成功后清除。PF、接口、网关、身份、心跳与恢复检查未放宽。结构不完整/重复服务/非法时钟等内部证据异常仍停止，不冒充网络超时。没有因缺失出口而停止的截止时间；lastVerifiedAt 不因失败刷新，日志保留 proofAge 和 retryAfterSeconds，不再报告旧 proofRemainingSeconds 截止。此时用户接受出口未确认，界面和菜单显示待核验，不能宣称已经验证持续出口。检测恢复后 15 秒周期恢复。


## 0.5.16 进程采集与防护门禁分离

`validatePreflight`/启动最终检查仍要求完整清单且 Claude 不存在；`validateProtection` 检查实际网络/PF前提，`MonitoringGate.validateDegraded` 是有意允许不完整进程清单的显式入口。它不修改事实字段，也不豁免其他保护条件。解除前继续使用完整清单与退出核验，不能证明就保留 PF。

ARMED 时 `.status`/`.inspect` 只返回监控状态；不再直接采集并触发停机。每秒监控和异步出口结果的本地重验共用一个单调时钟 5 秒复核窗口，不阻塞事务队列等待。代理核心必须从当前可读记录中找到、校验签名和生命周期，并具有真实网关连接/TUN。清单不完整时保留已追踪的 Claude 后代，未知缺席不能解释为已退出；完整扫描恢复后再刷新。状态包含可选 `claudeKnown`，按钮仍要求完整采集，不以 unknown 放行 IPv6 操作。

窗口内核心证据、PF 规则/引用/state、接口/TUN/实际路径、心跳或睡眠失效不延迟处理。窗口超时进入现有停止与恢复流程，若最终退出清单仍不完整则恢复受阻。现有合法路由通知重验策略保留，未泛化成忽略 epoch。

失败使用结构化 PID/stage/rc/errno，不靠错误字符串决定宽限。`last-monitoring-degradation.json` 及 `inventory-review` 事件记录 sessionID/时间、时长、次数、原生重试、追踪关联及首次恢复可读身份。只凭同 startTime 不声称发生 exec；没有此前身份不判断 PID 复用。该文件是最近一次事件，不代表始终存在当前异常。5 秒是逻辑期限，执行检查受系统调度影响，不承诺 CPU 完全饱和时硬实时响应。


## 0.5.17 Claude 构建重新登记

新增受认证 UI 专用 IPC `refreshClaudeRegistration`，不接受 UI 指定的路径、签名要求或 hash。仅在 OFF、无安全事务/启用标记、工具 anchor 为空、命令 worker 静止，且完整进程清单确认 Claude/Code 已退出时允许。签名核验后再次核对退出、资产和取消状态，再原子写入并回读安装登记；仅修改 claudeHash，当前进程随即使用新指纹，重启助手也可读取持久记录。

固定路径 `/Applications/Claude.app`，拒绝符号链接根目录。通过带截止时间的 codesign 深层、严格、全架构检查，要求包标识 `com.anthropic.claudefordesktop`、Apple Developer ID 链与 Anthropic 团队 `Q6L2SF6YDW`。验证前后比较构建 hash 与应用目录 inode，变化则拒绝。此验证不等于病毒扫描；开发者证书/团队改变需要发布者审阅后更新，不能任意信任新团队。

仅已登记桌面 UI、相同 UID/audit token/代码身份可调用；与 OFF 的排队取消机制一致。利用现有 root 助手授权，不弹新的管理员授权。登记不启用 PF、不调整 DNS/TUN/IPv6、不关闭仍在运行的 Claude，也不自动启动。写入失败时不在内存接受新 hash，下一次启动仍校验已登记指纹。用户在弹窗选择取消时不执行登记。

# 0.5.5 测试版：高负载心跳与阻断计数

版本 0.5.5+32，Apple Silicon / Intel，macOS 14+。本版不改变 PF 允许路径、不自动切换代理/TUN/DNS。

## 修复与新增

- 心跳发送和完成处理脱离主线程，防护期间避免 App Nap；不禁止系统睡眠。
- 启动验证仍要求 6 秒内心跳。已进入防护后，6 秒起提醒延迟，30 秒硬截止；期间保留 PF，继续强制核验防护前提。UI 真正退出、身份改变或防护失效仍停止。
- 单次心跳/状态通信失败不再由 UI 猜测并发送 OFF；状态不可确认时不显示绿色，守护进程仍负责超时和安全检查。
- 顶部玻璃提示框新增「已阻断数据包」。来自本工具 PF block 规则的实际数据包计数，整机范围、排除启动自检和此前流量，非恶意请求数、非 Claude 专属。重传也会增加计数。读取失败不显示假零；OFF 保留最后采样，下次会话重置。
- 反馈新增心跳年龄、最大间隔、监控间隔、UI 后台发送耗时与调度延迟。没有 CPU 样本时不会宣称 CPU 是故障原因。

## 手动验证与反馈

1. 先记录节点和自定义代理核心参数。在旧版菜单栏「恢复并退出」，使用 DMG 顶层移除工具，再双击安装新版；卸载会清空设置，需重新填写。不要只替换 UI。
2. 用户手动准备原代理/TUN。点击「仅验证防护」，确认 ARMED；访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，两者均应返回预期 IP。计数为 0 或自然增长都可能正常。
3. 正常关闭防护，再安全启动 Claude。重复之前引发误停的 Claude Code CPU 任务，持续至少 15 分钟；可将启动器置于后台，之后打开检查。预期不会仅因界面繁忙立即结束 Claude；真正异常仍会停止。无需人为占满整个系统。
4. 若要核对计数，在 **仅验证防护已 ARMED、Claude 未启动** 时记录计数，在终端执行 `dig @1.1.1.1 example.com +time=1 +tries=1 -b 本机物理IPv4`（将物理 IPv4 换成网络设置中的实际地址）。这是尝试绕过 TUN 的 UDP 查询，只能在已验证防护中执行。预期超时；若被本工具 PF 丢弃，计数在下一次监控后增长。系统 TUN/DNS 劫持可能改变路径，因此该步骤不能保证命中；有返回结果时先记录并停止测试，不单凭它断言泄漏。不要为了计数增长修改路由或关闭代理。
5. 点击「关闭防护」，应自行退出 Claude 后恢复为 OFF，保留最后计数而非继续增长。正常浏览网页确认恢复。
6. 导出反馈，附：版本、步骤时间、Claude 工作负载、是否切回启动器、计数前后值、黄色提示持续多久、两个出口结果。重复原先的 CPU 场景尤其有价值。

不要求人为杀死守护进程或暂停它；此类操作可能触发保留防护和恢复受阻。离线回归覆盖主线程阻塞、心跳延迟/硬超时、PF 变化、计数回退及通信失败。合成测试与打包核验不替代真实高负载和 Intel 真机验收。

## 兜底恢复（每轮测试保留）

安装器 → 恢复工具 → `恢复网络.command`，先选 **2** 清除本工具限制；仍断网选 **3**。核验受阻时阅读风险说明后输入 `UNPROTECT`，该操作可能停用整个 PF，影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网请重启 Mac 并保留输出。

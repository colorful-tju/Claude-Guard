# 0.5.10 测试版：兼容文件删除后仍存活的进程

版本 0.5.10+37，macOS 14+，Apple Silicon / Intel。临时签名，未获 Apple 公证；Intel 尚需真机验收。

## 修复范围

修复应用更新器的可执行文件已被删除、但进程仍存活时，出现 `Process identity unreadable ... stage=path ... errno=2`，导致进程采集不完整的问题。

仅 ENOENT 进入内核映射回退：要求唯一已删除可执行文件映射、内核进程名匹配、二次进程身份一致。权限不足、映射歧义、身份变化仍拒绝。不会忽略未知进程，不通过 ps/命令行参数猜测身份。PF、IP、IPv6 和退出策略不变。

## 验证与限制

新增真实临时子进程测试：启动测试文件、删除该文件、确认原路径 API 返回 ENOENT，再验证完整身份恢复。另覆盖多映射歧义、名称不符、权限失败、身份竞争及异常映射边界。测试仅操作自建临时进程，不删除其他应用文件，不启用 PF。

此修复需要可读取且唯一的内核映射证据，并非对全部身份读取失败放行。自动化测试不替代真机网络验收。

## 手动验收

1. 保存网络配置，旧版恢复并退出、确认 OFF。按 DMG 提示先卸载旧版再安装新版；卸载会清空配置。
2. 重新登记配置、点击重新检测。无其他异常时进程采集应完成，原 ENOENT 警告不再阻塞。无需主动删除任何文件。
3. 手动准备代理与 TUN，验证临时 IPv6 按钮，再执行仅验证防护。通过后正常关闭防护，确认 OFF、网页可用；之后测试 Claude 日常使用。
4. 如仍异常，导出反馈并附时间、具体按钮及错误。不要仅凭进程警告判断已进入防护。

## 兜底恢复（每轮保留）

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`，可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

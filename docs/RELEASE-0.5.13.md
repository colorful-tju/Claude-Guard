# 0.5.13 测试版：修复辅助接口路由通知误判

版本 0.5.13+40，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证，Intel 尚未真机验收。

## 定位与修复

0.5.12 的反馈显示，关闭前 11 秒两个 HTTPS 服务仍返回预期出口。关闭发生于运行态采集过程中：RTM_ADD 消息头的接口编号为 0，但正文的 IPv6 scope 和 AF_LINK gateway 都指向 awdl0。旧代码仅读取消息头，将本地无线协作接口的通知记为未知网络变化，采集恰好跨过通知就停止 Claude。本次记录不构成 IP 泄漏证据。

- 对完整、互相一致的 IPv6 链路本地路由正文恢复接口归属，随后仍按真实接口名称分类；不是忽略所有 index=0 消息。
- 公网、默认路由、重定向、范围过宽掩码、冲突 scope/index、截断或未知内容不获得辅助接口豁免。
- 不修改 PF，不扩大接口 allowlist，不放宽出口检查、心跳、探针或重试次数。采集遇到其他无法验证的变化仍停止。
- 日志补充原消息头接口编号，区分 Core 身份变化与采集前后 epoch，便于核查后续问题。

## 离线回归与限制

使用反馈中的 host 通知先复现旧代码失败，再验证修复；另覆盖地址轮换的 prefix 通知，以及公网、重定向、范围过宽、编号冲突、截断和异常长度反例。离线测试不代表公司 Wi-Fi 下的长期实机验收。

## 手动验证

1. 保存节点配置，关闭防护确认 OFF，再按 DMG 说明卸载旧版、安装新版本；卸载会清空设置。
2. 手动准备原代理/TUN与 IPv6 设置，先点击「仅验证防护」。确认 ARMED，访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，两个地址应返回预期出口。
3. 正常关闭防护，再点击安全启动 Claude。保持日常网络配置，使用对话、导出与 Code 任务至少 30 分钟；不必主动更改系统路由。
4. 导出反馈，记录 ARMED 起止时间、是否被关闭、错误时间与网页可用性。最后正常关闭防护，确认 OFF 和网络恢复。失败时直接保留报告，不反复尝试。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；选项 3 可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

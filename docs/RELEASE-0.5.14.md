# 0.5.14 测试版：为出口重试预留执行时间

版本 0.5.14+41，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证，Intel 尚未真机验收。

## 问题与修复

上一版在两轮出口检测失败后固定等待 10 秒，即使 45 秒出口证明期限只剩约 14 秒，也不缩短等待。最后一轮可能尚未完成，就触发 `Periodic egress proof expired: pending=true`。这不代表已经发现错误出口或泄漏。

本版按剩余期限安排重试：为单轮请求的 10 秒外层命令预算与 2 秒调度余量预留时间，实际等待为 `min(原等待, max(0, 剩余期限 - 12秒))`。正常仍间隔 6/10 秒；剩余时间不足时提前重试，不增加重试次数，不修改 PF。

45 秒绝对期限、第三次失败停止、错误公网 IP 立即停止、结果新鲜度与运行态核验均保持不变。若任务排队严重、网络持续失败或剩余期限不足，即使立即重试仍可能停止；不保证最后一轮必定完成，不延长安全期限。

## 验证范围

新增回归重放本次约 20.21 秒和 30.916 秒的两轮失败时间，验证第二轮等待由 10 秒缩短至约 2.084 秒；覆盖首轮已接近期限、正常退避、恢复成功、三次失败和硬期限。请求执行与调度共用命令超时常量，避免后续修改超时后预留预算失配。

## 手动验证

1. 保存配置，正常关闭防护确认 OFF；按 DMG 说明卸载旧版并安装新版。卸载会清空配置。
2. 手动准备原代理/TUN与 IPv6 设置，先做「仅验证防护」。ARMED 后访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，确认预期出口。
3. 正常关闭防护，再安全启动 Claude，重复日常安卓模拟器调试或 Code 工作至少 30 分钟。无需人为断网，也不要刻意改变路由。
4. 导出反馈，记录开始/结束时间、是否异常停止和模拟器操作时间。发生暂时检测失败时，`periodic-egress.retryAfterSeconds` 应随剩余期限缩短；网络持续不可核验时停止仍属预期。

本轮自动构建和测试不安装助手、不加载 PF、不切换代理。模拟器导致连接异常的因果关系尚未证实。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；选项 3 可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

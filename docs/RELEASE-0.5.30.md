# 0.5.30 测试版：前置连接协议验证

## 变化

旧版将 Core 的同端口连接列为候选，其中可能包含 DNS-over-HTTPS 等连接，不能据此判断机场入口。新版“验证前置连接”对这些候选使用所选节点的真实协议独立测试：

- 测试入口固定为候选 IPv4，保留原 TLS SNI、WebSocket Host 和路径，强制证书验证。
- 全局及节点均绑定指定物理接口；检查临时 Core 的实际 TCP 源地址、入口地址/端口、进程身份及 HTTPS 回显。
- 测试前后重新核对配置指纹、接口及活动 Core 候选。唯一结果填入入口；多个或没有结果不猜选。
- 明确区分“连接入口”和“前置出口”。不拿机场出口替换物理入口，不修改预期 ISP 出口。
- 原有 PF、正式启动、UDP 防护及恢复逻辑不变。测试结果不自动确认端点或启动防护。

## 隔离与限制

仅支持已登记 FLClash 0.9.3，且节点属于 VLESS WS+TLS、HTTP/SOCKS5 TCP 的安全参数子集。其他版本或参数明确拒绝。HTTP/SOCKS5 无 TLS 时，只测试原配置的数字 endpoint，避免向不相关候选发送明文认证。

本功能以普通用户运行临时 Core 副本，清除源文件的 setuid 权限，并核验签名身份；只使用自己新建的私有 IPC，不连接活动 Core 控制接口。关闭所有临时监听端口、TUN、DNS、NTP、provider、订阅、自动更新及持久化。配置通过私有 FIFO 传入，不保存包含密码的普通临时配置文件。退出或取消时关闭自己的连接、结束自己的子进程并删除临时目录；应用被强制结束时，Core 按宿主连接 EOF 退出，可能残留不含配置密码的临时目录。

这属于协议和连接诊断，不是抓包证明，也不证明 FLClash 所有请求的内层链路始终经过最终 ISP。正式防护仍以原有 PF/运行态/出口检查为准。当前构建的真实用户网络兼容性待手动验收；开发测试不切换代理、不加载 PF、不执行真实泄漏探针。

## 手动验收

1. 先关闭 Claude Guard 防护，保持当前可用代理。由你手动固定 FLClash 前置节点与 TUN，不要在测试中切换。
2. 网络设置读取“当前链路”，确认节点名称正确；先记录预期 ISP 出口。
3. 点击“验证前置连接”。每个候选有独立期限，最多 8 个候选；网络超时可能需一两分钟。可点卡片下方“取消前置验证”。
4. 预期：错误的同端口候选不会被填入；若唯一候选成功，展示入口及前置出口，填入入口但端点保持未确认；预期 ISP 出口应完全不变。
5. 如果多个候选均成功，停止猜选，反馈完整文字。若没有成功，反馈节点协议（不要密码）、Core 版本、候选和界面文字。
6. 再做取消测试，确认按钮恢复、代理仍正常，FLClash 当前节点/TUN 未变化。不要仅凭独立测试结果认为完整防护已开启。
7. 完成以上后，再由你按原手册确认端点、点击“仅验证防护”，检查正常出口及关闭后的网络恢复。开发阶段没有替你执行此步骤。

反馈请包含：macOS/FLClash/Guard 版本，所选节点类型，候选数，完整结果文字，预期出口是否保持，取消是否成功，是否改变了网络，以及“仅验证防护”的结果和导出报告。请勿发送代理密码或 UUID。

## 网络恢复兜底

本次独立前置测试不设置 PF、路由或系统代理。先取消测试；若应用无响应，退出启动器，勿结束正在使用的 FLClash Core。

如果后续正式防护测试影响网络，使用 DMG 安装器的“恢复工具”，或应用内“诊断与恢复 → 恢复工具”，按内置说明执行：优先正常恢复；仍无法恢复时用只清除本工具 filter 的强制恢复；仅最后明确选择模式 3（全局 PF 兜底，会影响其他 PF 防护）。恢复后不要直接重新启动 Claude，先保存反馈。

# 0.5.7 测试版：分散出口复检与 TLS 故障诊断

版本 0.5.7+34，macOS 14+，Apple Silicon / Intel。未获 Apple 公证；Intel 仍需真机验收。不修改 PF 规则、代理、TUN 或 DNS。

## 改进

- 快速失败后不再每隔 2 秒重试：第一轮失败后至少等待 6 秒，第二轮失败后至少等待 10 秒。避免三轮 TLS 快速失败集中在约 9 秒内，给短暂网络故障恢复机会。
- 仍以连续 3 轮失败或最后有效出口证据满 45 秒为停止条件，取先达到者。等待期间 PF、进程、接口、路由和心跳检查持续运行；45 秒不是保证等待满的宽限。任一非预期公网 IP 仍立即停止。
- TLS 诊断保留 curl 错误码，并从 stderr 提取固定错误特征，例如 `ssl-error-syscall`、`connection-reset`、`unexpected-eof`、`tls-alert`。不直接保存原始 stderr、网址、账号或网页正文；未知错误标为 `unclassified`，不猜测责任方。
- 反馈新增复检等待秒数和距 45 秒截止的剩余时间，便于判断是否过早重试。成功样本新鲜度仍为 10 秒，旧证据不能续期。

## 手动验证

1. 记录节点配置，旧版先「恢复并退出」，使用 DMG 移除工具卸载后双击安装新版；卸载会清空设置。不要只替换 UI。
2. 自行准备原代理/TUN，点击「仅验证防护」，应进入 ARMED。访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，均应为预期出口。
3. 正常关闭防护，再安全启动 Claude，按原工作方式使用至少 30 分钟。不要求故意断网、切换节点或占满 CPU。
4. 黄色复检提示出现时记录时间。若网络及时恢复，应恢复正常防护状态；持续失败仍会退出。导出反馈，附上黄色提示和停止时间、当时网页是否可用。重点保留 `periodicEgress`、服务错误特征、`retryAfterSeconds`、`proofRemainingSeconds`。
5. 正常关闭防护并核验 OFF、网页恢复。离线测试覆盖快速失败间隔、恢复、非预期 IP 立即停止、绝对截止及诊断脱敏。不能用本版判断以前的 TLS 故障一定由哪一方引起。

## 兜底恢复（每轮测试保留）

安装器 → 恢复工具 → `恢复网络.command`，先选 **2** 清除本工具限制，仍断网选 **3**。核验受阻时阅读风险说明后输入 `UNPROTECT`，可能停用整个 PF、影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启 Mac 并保留输出。

# 0.5.8 测试版：补齐启动 HTTPS 探针错误

版本 0.5.8+35，macOS 14+，Apple Silicon / Intel。未获 Apple 公证，Intel 仍需真机验收。

## 修复范围

修复启动验证中的错误信息丢失：此前单个服务的错误被 `try?` 丢弃，最终只显示 `Probe worker failed at dual-https, exit=1`。现在反馈记录 ipify 和 Webshare 各自成功/失败/未完成、耗时及脱敏错误；界面原始详情保留具体摘要。

curl 失败保留退出码和固定 TLS 错误特征；命令期限、取消、未知错误分开记录。未知异常不直接输出原文，避免泄漏凭据或响应内容。外层汇总超时也保留当时已完成的服务结果。

本版没有证明或修复此前连接失败的网络根因。启动仍要求两个服务成功并符合预期出口；不允许部分结果进入 ARMED。PF 规则、启动期限、运行期 6/10 秒复检及 45 秒硬截止均不变。

## 手动验证

1. 记下网络设置，旧版「恢复并退出」，通过 DMG 移除后安装新版；卸载会清空设置，不要只替换 UI。
2. 自行准备原代理/TUN，点击「仅验证防护」一次。若通过，应进入 ARMED；正常访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，核对出口，再关闭防护。
3. 若再次在 dual-https 阶段失败，不需要连续重复。导出反馈并附点击时间，以及普通 IP 检测在防护 OFF 时的结果。新版应给出两个服务各自结果，例如 `curl exit=35 detail=ssl-error-syscall`，不能仅凭该标签认定服务商或本地防火墙有责任。
4. 确认 OFF 和网页恢复后，将反馈交回分析。不要为取得错误详情关闭 TLS 验证或放宽 PF。

## 兜底恢复（每轮测试保留）

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`，可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

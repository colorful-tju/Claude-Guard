# 0.5.9 测试版：细化网络事件失效判断

版本 0.5.9+36，macOS 14+，Apple Silicon / Intel。未获 Apple 公证；Intel 尚需真机验收。

## 修复范围

此前全局网络事件计数直接写入每个接口的 generation，重复接口状态通知也会表现为所有接口同时变化。现在仅对已建立语义基线、非统计字段完全一致的 RTM_IFINFO 做去重，不因收发计数变化关闭 Claude。

地址增删、路由变化、状态/MTU/管理变更时间变化、未知消息、读取失败仍保持保守停止；不会忽略所有 epoch 差异，不会自动放行新增接口。PF 规则、启动负向探针、出口要求和退出恢复顺序未更改。补充路由重定向与未知通知的保守处理。

反馈新增 networkEvents，最多记录最近 32 条相关事件的时间、数字类型、接口、索引、失效代次、决策及状态签名。历史故障没有事件类型，无法追溯证明那次必然是重复 IFINFO；本版修复已确认的粗糙分类，并保留进一步定位能力。

## 手动验证和反馈

1. 保存当前网络设置，旧版「恢复并退出」确认 OFF，按 DMG 提示卸载并安装 0.5.9。卸载会清空用户配置，重新登记实际核心和节点。无需更改代理方案。
2. 由你手动准备代理/TUN及临时 IPv6。先点「仅验证防护」，应进入 ARMED；访问 https://api.ipify.org/ 和 https://ipv4.webshare.io/，两个出口均应符合预期。
3. 正常关闭防护，再「安全启动 Claude」，进行日常对话、Claude Code 开发及文件导出，建议覆盖 30 分钟。不要为了本轮测试主动切换网络或节点。
4. 正常结束时点击「关闭防护」，确认 Claude 退出、OFF 和网页可用。导出反馈，提供开始/结束时间、是否自动关闭、当时的操作与是否休眠。若再次自动停止，立即导出反馈；应能看到 networkEvents，不必反复重试。

自动化回归覆盖重复 IFINFO、统计字段变化、管理时间/MTU/flags 变化、down/up、未知接口、地址/路由变更。合成测试不替代真实 PF 与长时间运行验收；本轮开发不自动启用 PF、启动 Claude或切换代理。

## 兜底恢复（每轮测试保留）

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`，可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

普通 UI 导出的反馈中，事件出现在 report 的 `network-event` 行；助手完整诊断同时保留结构化 `networkEvents` 数组。

# 0.5.26 测试版：启动阶段网关短连接采样复核

版本 0.5.26+53；macOS 14+，Apple Silicon / Intel。临时签名、未获 Apple 公证；Intel 未真机验收。

## 针对性修复

出口探针完成后，HTTP 代理的连接可能已结束。此前最终快照若恰好采不到已建立的网关连接，会立即拒绝启动，即使两项出口和物理接口阻断探针刚刚成功。

现在仅在最终运行态采样“没有已建立的目标网关连接候选”时，保持 PF 并检查规则、引用、state、网络代次及取消状态，最多重新执行一轮完整 TCP/UDP/STUN 阻断探针和 HTTPS 出口检测。上一轮结果不会用于启动；第二轮仍须取得全新的完整运行态和最终快照，包含真实已建立的网关连接。

- 不把历史连接、超时或正确出口单独当作网关验证通过。
- 有连接但物理地址/身份等不一致，不走此重试。
- 与已有网络代次重试共享两轮上限，不无限重试，不延长原有证据有效期。
- 重试期间不启动 Claude、不移除 PF；持续缺证据仍拒绝，走原有安全恢复。
- 不改变稳态监控、出口判定、PF 放行范围或恢复机制。

## 复测

1. 按 DMG 说明退出旧版防护、卸载并安装新版；手动准备原来的代理及 TUN。
2. 确认端点、预期出口、IPv6 条件后，先点“仅验证防护”。
3. 若出现连接采样空窗，应显示“保持防护，重新完整验证（第 2/2 轮）”；日志包含 `startup gateway-socket recheck 2/2`。
4. 只有第二轮完整探针和最终快照通过才进入 ARMED。验证通过后再测“安全启动 Claude”。
5. 若仍失败，导出反馈，记录点击时间及当时使用直连 ISP 还是链式代理。此版本不新增链式代理支持。

离线回归涵盖短暂缺失、持续缺失、接口变化、PF 规则/引用变化、网络代次变化及用户取消。真实网络复现需用户手动验收；不能保证持续无连接的环境一定启动成功。

兜底：优先“关闭防护/恢复并退出”。恢复受阻时使用应用或安装器中的“恢复工具 → 恢复网络.command”，先选 2，仍断网再选 3，并按实际提示确认；强制恢复会解除保护，模式 3 可能影响整个 PF，不属于正常 OFF 验收。仍异常可重启并保留反馈。

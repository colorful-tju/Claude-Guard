# 0.5.23 测试版：Claude 主进程退出核验修复

版本 0.5.23+50；macOS 14+，Apple Silicon / Intel。临时签名，未获 Apple 公证；Intel 未真机验收。

## 修复

已追踪的 Claude Desktop 主进程可能在退出期间无法通过 libproc 读取完整身份，但内核仍确认它存在。旧版无法发送结束信号，又无法确认退出，导致恢复受阻。

终止阶段新增独立内核核验路径，仅用于此前确认的标准安装位置 Claude 主进程。连续两次完整记录确认身份稳定，核对内核名称 Claude、PID、启动时间和安装用户 UID 后，才允许尝试结束。身份不符或无法核验时不发送信号。

该路径不参与普通进程分类，不把信号成功视作退出，不允许不完整清单通过 OFF 验收。Claude Code 和任意工具子进程不使用这条备用路径，保持原处理。

## 边界

不修改 PF、代理策略、现有重试上限或同次开机助手重启保护。内核查询也失败、进程无法结束或其他未知进程持续存在时，仍可能恢复受阻。核验至发送信号不是原子操作；不宣称消除了全部 PID 竞态或解决所有 macOS 进程卡死。

## 更新与验证

1. 保存工作，正常恢复 OFF 后按 DMG 说明卸载旧版并安装。已使用应急恢复且旧事务无法收尾时，保存工作后重启 Mac，暂不启动 Claude，等待恢复；仍失败时保留记录，不删除事务文件。
2. 手动准备代理/TUN，先运行“仅验证防护”。再安全启动 Claude，完成对话或工具调用后从 Claude 菜单退出，观察能否回到 OFF。
3. 再次安全启动 Claude，改用启动器“关闭防护”，确认 Claude 退出且恢复 OFF。不要手动杀死助手来模拟故障。
4. 失败时导出反馈并运行只读事故采集，保留 events.log、last-termination.json。新路径会记录 termination-lifetime-fallback；正常退出不必出现该标记。

离线回归与错误注入不等于真实故障现场验收；开发中未操作用户代理、PF、TUN 或 IPv6。

兜底：安装器 → 恢复工具 → 恢复网络.command，先选 2，仍断网选 3（可能停用整个 PF，影响其他防火墙）；按工具要求确认 UNPROTECT。仍断网请保存工作后重启，不删除恢复事务。

# 0.5.22 测试版：进程退出与应急恢复收尾

版本 0.5.22+49，macOS 14+；提供 Apple Silicon / Intel 安装包。临时签名，未获 Apple 公证，Intel 未真机验收。

## 修复

- 卸载失败保留助手原加载状态：原本通过应急工具停止的助手不会被自动重新启动；无法读取原状态时不改变服务。
- 完整进程清单已恢复且 PF/运行态核验通过时，不再仅因复核超过 5 秒停止。仍不完整时保留原来的严格处理。
- 发送结束信号后最多进行 3 次完整清单复核，额外等待合计 0.4 秒；未确认退出不能解除 PF。
- 保留终止过程中发现的子进程身份到后续恢复重试。进程脱离父进程后仍按 PID 与启动时间追踪，PID 复用不能授权错误杀进程。
- 补充 sysctl/kill(pid,0) 的存在性查询诊断，以及逐目标信号结果；详细结果写入 last-termination.json，失败摘要进入反馈记录，只读采集包含新文件。
- 恢复受阻及卸载提示解释应急恢复与完整 OFF 的差别，并给出收尾路径。

## 边界

这不是“忽略未知进程”的版本。未追踪不代表无关，errno=3 不直接代表已退出；PF、代理核心、TUN、权限和完整退出验收仍保留。旧日志不足以还原此前 PID 的内核状态，不能宣称该类故障彻底消失。助手同一次开机重启后无法确认旧 worker 时，仍不自动清理不明事务；必要时需重启 Mac。

## 当前受阻用户如何更新

1. 保存工作，退出 Claude/Code。若已应急解除阻断，先不要反复打开旧卸载器。
2. 保存工作后重启 Mac，暂不启动 Claude。等待旧助手恢复旧事务，确认 OFF 和 IPv6 原设置恢复。
3. 若仍失败，保留错误与反馈；不要手工删除事务、引用文件。
4. 按新 DMG 说明卸载再安装。新 DMG 的移除工具含修复，但不会绕过旧事务检查。

## 验证

先“仅验证防护”，再安全启动 Claude，进行一次正常对话、工具调用与关闭。正常关闭应结束受保护进程后回到 OFF。失败时导出反馈并使用内置事故采集，保留 last-termination.json。不要人为杀助手或创建未知进程来做在线故障注入；相关分支以离线模拟验证。

本次构建与离线测试不等于真实网络/Intel 真机验收。开发过程中没有操作用户网络或安装助手。

兜底：安装器 → 恢复工具 → 恢复网络.command，先选 2，仍断网选 3（可能停用整个 PF，影响其他防火墙）；受阻按说明确认 UNPROTECT。仍断网请重启并保留输出。

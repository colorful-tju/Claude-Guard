# 0.5.17 测试版：Claude 更新后在报错弹窗重新登记

版本 0.5.17+44，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证；Intel 尚未真机验收。

## 新增功能

当安全启动提示 `Claude build changed; reinstall registration`，弹窗提供 **验证并重新登记 Claude**。这是 Claude 更新后指纹与旧登记不一致，不是网络泄漏判定。

1. 先退出 Claude Desktop 与 Claude Code，确认防护已恢复 OFF。
2. 点击弹窗按钮，助手核验当前 Claude 的官方签名并更新指纹。
3. 成功后再次点击「安全启动 Claude」。不自动启动，也不改变节点、DNS、TUN、IPv6 设置。

使用已安装助手的权限，每次重新登记不额外请求管理员密码。首次安装/升级助手仍需要管理员授权。

## 安全边界

只接受固定位置、固定 Anthropic 团队及包标识，并验证 Apple Developer ID 签名链、深层资源和所有架构；签名无效、非官方团队、验证期间构建/目录变化会拒绝。必须取得完整进程退出证据。仍有防护事务、恢复受阻或未清理的本工具规则时，不允许登记。只更新 Claude 指纹，网关、核心、UI 授权身份等登记保持原值。写入与回读确认完成后才在内存接受新指纹。

沿用 0.5.16 的进程复核策略及原有 PF、出口和恢复逻辑。

## 验证方法

- 本次升级到 0.5.17 仍按 DMG 的旧版恢复退出、卸载、安装流程操作，先记下网络配置。新安装会登记当前 Claude，因此通常不会立刻弹出更新提示。
- 正常完成「仅验证防护」与 OFF，再安全启动 Claude，检查原有流程。
- 下次 Claude 正常更新后，再安全启动。预期先回到 OFF，弹窗说明版本变化并出现登记按钮。先关闭 Claude/Code，再点击登记；成功后重新安全启动，且重启防护器后仍能使用。
- 选择「知道了」应不登记；签名或进程检查失败应保留错误并允许退出，不自动关闭正在运行的 Claude，也不放行启动。
- 不要修改签名、安装记录或真实 PF 来制造测试场景。失败、并发变化和写入异常已有离线注入覆盖；真实更新验收需等待正常更新事件。
- 反馈请附版本、弹窗文字、操作时间、登记后启动是否正常，以及导出的 JSON。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；选项 3 可能停用整个 PF 并影响其他防火墙，不等于正常 OFF 验收。不要继续使用 Claude；仍断网则重启并保留输出。

# 0.5.18 测试版：修复高负载下重复解析配置导致的误停

版本 0.5.18+45，macOS 14+；Apple Silicon / Intel。临时签名，未获 Apple 公证；Intel 尚未真机验收。

## 修复

此前持续监控每轮都会启动 Ruby 读取代理 YAML；在高 CPU 占用时，本地解析步骤可能超过 8 秒，继而保守关闭 Claude。该错误不等于检测到 IP 泄漏。

现在每次仍读取并核验配置的完整内容，内容指纹未变化时复用已验证解析结果，消除这一重复启动解释器的路径。配置变化必须重新解析；文件不可读、类型/所有者异常、超过大小限制、读取或解析中发生变化仍拒绝，不使用过期结果放行。Ruby 通过 stdin 解析已读取的字节，并核对指纹。

实际 Core 身份、到网关的连接、TUN、PF 规则/state、出口策略和恢复顺序不变；未延长全部命令超时，未将所有超时视作可忽略。系统严重过载导致其他关键证据失效仍可能停止。

## 验证与反馈

1. 先正常关闭防护，按 DMG 说明卸载旧版并安装新版，提前保存网络配置。
2. 手动准备代理，进行「仅验证防护」并正常关闭，再安全启动 Claude。
3. 正常使用，包括原先会引发 CPU 高负载的任务；观察是否仍发生 ruby 超时。无需故意修改已登记配置或破坏网络。
4. 正常关闭防护，导出反馈。若发生异常，请附操作时间、CPU 负载场景、完整提示及反馈文件。

本轮验证为离线回归、文件读取与解析测试及安装包校验，不代替用户真实满载会话验收。

## 兜底恢复

安装器 → 恢复工具 → `恢复网络.command`，先选 **2**，仍断网选 **3**。核验受阻时阅读说明后输入 `UNPROTECT`；选项 3 可能停用整个 PF 并影响其他防火墙。不要继续使用 Claude；仍断网则重启并保留输出。
